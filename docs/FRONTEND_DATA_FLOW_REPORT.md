# FRONTEND DATA FLOW AUDIT

**Date:** 2026-06-18
**Audit:** Trace every admin module's complete data path: admin → API → DB → frontend

---

## DATA FLOW MAP

### A — FULLY CONNECTED (4 modules)

#### 1. Opportunities (Arbitrage)
`
Admin /admin/opportunities (CRUD)      → POST/PUT/DELETE /api/admin/opportunities
  → opportunities table (001_schema)   → GET /api/opportunities (public, filters: search/league/risk/roi)
  → Frontend: /opportunities (list), /opportunity/[id] (detail), /dashboard (summary)
`
Data source: Admin-created OR seed data (5 hardcoded INSERTs). **After admin creates, it immediately shows on frontend** on next page load. No real-time push.

#### 2. Wallets (Payment Addresses)
`
Admin /admin/payment/wallets (CRUD)    → POST/PUT/DELETE /api/admin/payment/wallets
  → wallets table (sql/021 schema)     → GET /api/public/wallets (public, enabled=true filter)
  → Frontend: /deposit (DepositModal.tsx — fetches wallets on mount)
`
Data source: **Real DB.** Admin creates/edits wallets → user sees them in deposit page on next load. Fully functional CRUD.

#### 3. Notifications
`
Admin /admin/notifications (create/send) → POST /api/admin/notifications
  → notifications table (001_schema)    → GET /api/notifications?userId=X (user-side)
  → Frontend: NotificationCenter.tsx, AuthStore (fetches unread count)
`
Data source: **Real DB.** Admin sends notification → stored in table → user sees it on page refresh.

#### 4. Winning Feed
`
No admin UI needed                     → (read-only, auto-generated)
  → activity_feed + unlocks + deposits  → GET /api/public/winning-feed
  → Frontend: WinningFeed.tsx (polls every 15s)
`
Data source: **Real DB.** Activity feed from unlocks/deposits. Auto-generated by user actions. Polls every 15 seconds.

### B — NEEDS REFRESH (1 module)

#### 5. Users / VIP Level
`
Admin /admin/users (edit vip_level)    → PATCH /api/admin/users (updates profiles.vip_level)
  → profiles table (001_schema)        → GET /api/auth/me (user's own profile)
  → Frontend: /profile, /dashboard, /vip (read from authStore which fetches profile)
`
Data source: **Real DB.** Admin changes vip_level → user sees it on next page load. **VIP Page tiers are hardcoded** (Explorer/Bronze/Silver etc. defined in page.tsx tiers array — NOT from DB).
